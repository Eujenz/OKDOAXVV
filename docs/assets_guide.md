## 基本概念

### 什麼是「模板」？

模板是一張 **1280×720 白底全螢幕 PNG 圖片**，上面只保留你想比對的 UI 元素（按鈕、文字等）。
框架在執行時會用這張圖與遊戲畫面進行**模板比對 (Template Matching)**，找到匹配的位置後自動點擊。

### 兩個工具的分工

| 工具 | 用途 | 何時使用 |
|------|------|----------|
| **TemplateMakerTask**（模板製作工具） | 截取遊戲畫面 → 框選 ROI → 自動儲存圖片 + 更新 JSON | 新增或更新**單一**模板 |
| **JsonFixerTask**（魔法修復 JSON 工具） | 掃描 `images/` 資料夾 → 自動重建完整 `result.json` | 手動增刪/重命名圖片檔案後，一鍵修復 JSON |

### 運作原理圖

```
┌─────────────────────────────────────────────────────┐
│                  TemplateMakerTask                   │
│                                                     │
│  擷取遊戲畫面 → cv2.selectROI 框選 → 存成白底 PNG    │
│                    ↓                                │
│            自動寫入 result.json (COCO 格式)           │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│                   JsonFixerTask                      │
│                                                     │
│  掃描 assets/images/*.png → 從白底圖反推 bbox 座標    │
│                    ↓                                │
│            完整重建 result.json                       │
└─────────────────────────────────────────────────────┘
```

## 資料夾結構

```
assets/
├── images/          ← 模板圖片（白底 PNG）
│   ├── 01.png       ← 競賽選單按鈕
│   ├── 02.png       ← 推薦選單按鈕
│   ├── 03.png       ← 最高難度關卡
│   ├── 03-weak.png  ← 較弱關卡（變體）
│   ├── 04.png       ← 進行挑戰按鈕
│   ├── ...
│   └── 12.png
└── result.json      ← COCO 格式的模板索引檔
```

### result.json 格式說明

```json
{
  "images": [
    { "id": 1, "file_name": "images/01.png", "width": 1280, "height": 720 }
  ],
  "categories": [
    { "id": 1, "name": "01" }
  ],
  "annotations": [
    { "id": 1, "image_id": 1, "category_id": 1, "bbox": [40, 193, 65, 35], "area": 2275 }
  ]
}
```

| 欄位 | 說明 |
|------|------|
| `images` | 圖片檔案的路徑與全螢幕尺寸 |
| `categories` | 模板名稱（= 檔名去掉 .png），用於 `find_one('01')` |
| `annotations` | ROI 的位置 `[x, y, width, height]` 與面積 |

## 正常流程：從零開始建立模板

### 前置條件

- ✅ 遊戲視窗 **DOAX VenusVacation** 已開啟
- ✅ 遊戲畫面停留在你想擷取的 UI 頁面上
- ✅ ok-script 程式已啟動

### 步驟一：新增模板

1. 在 ok-script 的任務清單中找到 **「模板製作工具」**
2. （可選）在設定欄位 **「模板名稱」** 中輸入自訂名稱
   - 留空 → 自動遞增編號（`01`, `02`, `03`...）
   - 輸入名稱 → 使用你指定的名稱（如 `03-weak`）
   - 輸入已存在的名稱 → 覆蓋更新該模板
3. 點擊 **執行**
4. 畫面會彈出 **「Template Maker」** 視窗，顯示目前的遊戲截圖
5. **用滑鼠框選**你想比對的 UI 元素區域（按鈕、文字等）

> **框選操作**：
> - 按住左鍵拖曳出矩形區域
> - 放開左鍵確認範圍
> - 按 **Enter** 確認 ✅
> - 按 **ESC** 取消 ❌

6. 確認後，工具會自動：
   - 儲存白底 PNG 到 `assets/images/`
   - 更新 `assets/result.json`
   - 在日誌中顯示模板名稱、座標、使用範例

### 步驟二：驗證模板

確認日誌輸出類似以下內容：

```
📸 準備截取模板 [04]，框選區域後按 ENTER 確認，ESC 取消。
✅ 已儲存: assets\images\04.png
   名稱: 04  大小: 97x40  座標: (985,652)
   全螢幕: 1280x720

   💡 在 flow.json 中使用:
   { "feature": "04", "label": "描述", "action": "click", "priority": 50 }

   💡 在 Python 中使用:
   self.find_one('04')
```

### 步驟三：重複以上步驟

對每個需要比對的 UI 元素重複步驟一和二，直到所有模板建立完畢。

**建議的建立順序**（以刷活動流程為例）：

| 順序 | 模板 | 對應畫面 |
|------|------|----------|
| 1 | `01` | 競賽選單按鈕 |
| 2 | `02` | 推薦選單標籤 |
| 3 | `03` | 最高難度關卡 |
| 4 | `03-weak` | 較弱關卡（可選） |
| 5 | `04` | 進行挑戰按鈕 |
| 6 | `05` | ALL SKIP 按鈕 |
| 7 | `06` | 確定 / 結算按鈕 |
| 8 | `07` | RESULT 畫面標題 |
| 9 | `08` | 獎勵畫面 |
| 10 | `09` | 體力耗盡提示 |
| 11 | `10` | 喝 100 體力水按鈕 |
| 12 | `11` | 喝滿體力水按鈕 |
| 13 | `12` | 確認回復按鈕 |

## 日常維護操作

### 情境 A：更新單一模板（遊戲 UI 改版）

1. 開啟 **模板製作工具**
2. 在 **「模板名稱」** 欄位輸入要更新的模板名稱（例如 `04`）
3. 執行 → 框選新的 UI 元素 → Enter 確認
4. 工具會自動覆蓋舊圖片和 JSON 條目

```
⚠️ 模板 [04] 已存在，將覆蓋更新。
✅ 已儲存: assets\images\04.png
   (覆蓋更新模板 ID=5)
```

### 情境 B：手動刪除模板

1. 直接刪除 `assets/images/` 中不需要的 PNG 檔案
2. 執行 **「魔法修復 JSON 工具」** (JsonFixerTask)
3. result.json 會自動重建，清除已刪除圖片的條目

### 情境 C：手動重新命名模板

1. 在檔案總管中重新命名 PNG 檔案（例如 `05.png` → `skip_all.png`）
2. 執行 **JsonFixerTask**
3. JSON 會自動使用新的檔名作為 category name

> ⚠️ **注意**：重新命名後，必須同步更新 `flows/event_farming.json` 中對應的 `"feature"` 欄位。

### 情境 D：從外部匯入模板圖片

如果你從其他來源取得已截好的模板圖片：

1. 確保圖片格式為 **白底 PNG**（非白色區域即為 ROI）
2. 將圖片放入 `assets/images/` 資料夾
3. 執行 **JsonFixerTask** 自動重建 JSON

### 情境 E：初始化全新的 assets 資料夾

如果 `assets/images/` 是空的：

1. 執行 **TemplateMakerTask**，工具會自動初始化 `result.json`：
```
ℹ 圖片資料夾為空，已初始化 result.json。
```
2. 接著按正常流程建立模板即可

## 與 Flow JSON 的整合

建立好模板後，在 `flows/event_farming.json` 中引用模板名稱：

```json
{
  "id": "challenge",
  "label": "進行挑戰",
  "feature": "04",        ← 對應 assets/images/04.png 的 category name
  "action": "click",
  "priority": 50,
  "on_success": "increment_count"
}
```

### 使用變體 (Variants)

同一步驟可根據設定使用不同模板：

```json
{
  "id": "select_stage",
  "feature": "03",              ← 預設使用 03.png
  "variants": {
    "關卡模式": {
      "較弱關卡": {
        "feature": "03-weak",   ← 切換使用 03-weak.png
        "label": "較弱關卡"
      }
    }
  }
}
```

### 在 Python 程式碼中使用

```python
# 搜尋模板
box = self.find_one('04', threshold=0.75)

# 搜尋並取得座標
if box:
    print(f"找到了！位置: ({box.x}, {box.y}), 信心度: {box.confidence}")
```

## 疑難排解

### ❌ 問題 1：「無法擷取畫面！請確認遊戲視窗已開啟。」

**原因**：遊戲視窗未開啟，或視窗標題不符。

**解決方案**：
1. 確認遊戲 **DOAX VenusVacation** 已啟動且未最小化
2. 確認 ok-script 已正確偵測到遊戲視窗（主介面應顯示已連線）
3. 如果遊戲剛啟動，等待幾秒讓畫面穩定後再執行

---

### ❌ 問題 2：「讀取檔案失敗」（JsonFixerTask 報錯）

**原因**：`assets/images/` 中有損壞或格式不正確的圖片。

**解決方案**：
1. 到 `assets/images/` 資料夾檢查是否有非 PNG 格式的檔案
2. 嘗試用圖片檢視器開啟報錯的檔案，確認是否能正常顯示
3. 刪除損壞的檔案後重新執行 **JsonFixerTask**

---

### ❌ 問題 3：模板建立成功，但執行時 `find_one` 找不到

**可能原因與對策**：

| 原因 | 檢查方式 | 解決方案 |
|------|----------|----------|
| 框選範圍太大，包含會變動的背景 | 查看截圖中非白色區域的範圍 | 重新截取，只框選**不會改變的固定 UI 元素**（如按鈕文字） |
| 框選範圍太小，特徵不足以區分 | 確認 bbox 面積是否過小 | 適當擴大框選範圍，包含按鈕的邊框或圖示 |
| 辨識門檻設定過高 | 查看日誌中的相似度數值 | 將 `辨識門檻` 從 0.75 降低到 0.65~0.70 |
| 遊戲解析度改變 | 確認遊戲視窗是否為 1280×720 | 保持一致的解析度，或重新截取模板 |
| 遊戲UI已更新 | 比對舊截圖和新畫面 | 用 **TemplateMakerTask** 重新截取該模板 |

---

### ❌ 問題 4：框選時按了 Enter，但模板看起來不對

**解決方案**：
1. 到 `assets/images/` 用圖片檢視器開啟剛儲存的 PNG
2. 確認白底圖上的 ROI 區域是否正確
3. 如果不對，用**相同的模板名稱**重新執行 TemplateMakerTask（會自動覆蓋）

---

### ❌ 問題 5：JsonFixerTask 執行後，某些模板的 bbox 座標不對

**原因**：模板圖片中的 UI 元素包含**純白色像素**（灰度值 ≥ 254），導致白底反推時該區域被忽略。

**解決方案**：
1. 用 **TemplateMakerTask** 重新截取該模板（TemplateMakerTask 使用框選座標直接寫入 JSON，不依賴白底反推）
2. 避免在截取後執行 **JsonFixerTask**（除非你確實需要重建整個 JSON）

> 💡 **結論**：如果你只是更新單一模板，用 **TemplateMakerTask** 即可，它會精確記錄座標；**JsonFixerTask** 適合用在大量批次操作後的整體修復。

---

### ❌ 問題 6：新增模板後，FlowRunnerTask 不認得新的 feature 名稱

**原因**：`flows/event_farming.json` 中沒有對應的步驟。

**解決方案**：
在 `flows/event_farming.json` 的 `"steps"` 陣列中新增一筆：

```json
{
  "id": "new_step",
  "label": "你的步驟描述",
  "feature": "新的模板名稱",
  "action": "click",
  "priority": 50
}
```

---

### ❌ 問題 7：執行 JsonFixerTask 把手動調整過的 JSON 覆蓋了

**原因**：JsonFixerTask 會**完整重建** result.json，不保留手動修改。

**解決方案**：
- 在執行 JsonFixerTask 前，先備份 `assets/result.json`
- 如果只需要更新單一模板，使用 **TemplateMakerTask** 而非 JsonFixerTask

## 注意事項與限制

### 📏 框選技巧

1. **只框選固定不變的元素** — 避免包含動態背景、動畫特效、數字等會變動的區域
2. **夠小但夠獨特** — 框選範圍要小到只包含目標元素，但要包含足夠的特徵讓 Template Matching 能區分不同的按鈕
3. **避免框選邊緣太貼** — 框選時留一點點邊距，避免框到邊界像素

### ⚡ 兩個工具的選擇時機

```
需要做什麼？
 │
 ├─ 新增 / 更新單一模板 ──→ 使用 TemplateMakerTask ✅
 │
 ├─ 手動增刪了多張圖片 ──→ 使用 JsonFixerTask ✅
 │
 └─ 剛從別人那裡複製了整個 images/ 資料夾
    ──→ 使用 JsonFixerTask ✅
```

### ⚠️ 已知限制

1. **JsonFixerTask 的解析度**：重建 JSON 時，圖片的 `width` / `height` 會固定為 `1280×720`，如果你的遊戲解析度不同，需要手動修正或使用 TemplateMakerTask 逐一更新
2. **白色 UI 元素**：如果按鈕本身是純白色的，JsonFixerTask 在反推 bbox 時可能會不精確（白底和按鈕顏色無法區分），建議此情境使用 TemplateMakerTask
3. **批次操作**：目前不支援一次框選多個 ROI，每個模板需要獨立執行一次 TemplateMakerTask
